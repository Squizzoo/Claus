Code signing policy

How the Windows builds of Claus are built, approved and signed, who is responsible for that, and what the app sends over the network.

Free code signing provided by SignPath.io, certificate by SignPath Foundation

Team and roles

Claus is a small open-source project. Every signed release goes through the three roles below. A role can be held by the same person; nothing is signed without an explicit approval.

RoleWhat it doesWho
Authors and committersWrite the code and push it to the repository.Squizzoo
ReviewersReview changes before they reach main.Squizzoo
ApproversApprove the release in GitHub (the release environment) and the signing request in SignPath.Squizzoo

Everyone on the team must use two-factor authentication on GitHub and on SignPath.

What is signed, and how

  • Only the installer (Claus-Setup-x.y.z.exe) and the portable program (Claus-x.y.z-portable.exe) are signed, and only builds made from the public source code.
  • Builds are made by a GitHub Actions workflow on a GitHub-hosted runner, from a version tag. The workflow runs the tests, checks that the product name is Claus and that the tag matches the version in package.json, and then sends the build to SignPath for signing. Nobody signs on their own computer.
  • Every release has to be approved by hand in GitHub before it is published, and every signing request has to be approved in SignPath.
  • Each release carries a build provenance attestation and a SHA256SUMS.txt file, so a download can be checked against the workflow that built it: gh attestation verify <file> --repo Squizzoo/Claus.
  • Claus is not malware or a potentially unwanted program and does not try to hide what it does. It will not be signed if it is.

Privacy policy

Claus works on your computer. It has no accounts, no telemetry and no analytics. What it reads and where it goes:

  • Claude Code hooks deliver events to Claus on 127.0.0.1, your own computer. Claus keeps only the chat id, the event name, the tool name and the project folder. Prompts and tool input are dropped.
  • Settings and counters (position, look, a count of chats finished today) are saved in a file on your computer. They are never sent anywhere.
  • The update check is the only automatic network request. Claus asks github.com (the releases of this project) whether a newer version exists. GitHub sees your IP address, as any website does; Claus sends nothing about you, your chats or your computer. Nothing is downloaded or installed without a click. You can switch it off under Settings > System > Updates > Check for updates automatically; after that Claus only asks when you press Check for updates.
  • Choosing a version (Settings > System > Updates) asks api.github.com for the list of releases, only when you press Show versions.

Claus does not transfer any other information to other networked systems unless you ask it to. GitHub's own privacy statement applies to requests that reach GitHub.

Reporting a problem

If you think a signed build of Claus is misbehaving, or a certificate has been misused, please open an issue. Signed builds that turn out to be harmful will be reported to SignPath so the certificate can be revoked.
